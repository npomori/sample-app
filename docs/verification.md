# 動作確認

この文書では、認証サーバーとの接続後に行う手動確認について説明します。仕様は [participant-app.md](https://github.com/npomori/auth-server/blob/main/planning/participant-app.md) を参照してください。参加アプリのホストは `APP_ORIGIN`、認証サーバーのホストは `AUTH_ORIGIN` です。

## 前提

認証サーバーの管理画面で、このアプリを登録します。

| 項目           | 値                                                                             |
| -------------- | ------------------------------------------------------------------------------ |
| アプリ ID      | Coolify または `.env` に設定した `APP_ID` と同一。表示名は引き渡しに使いません |
| オリジン       | `APP_ORIGIN`。パスは含めない                                                   |
| 戻り先 URL     | `APP_ORIGIN/callback`                                                          |
| 既定の利用許可 | `allow`、または「利用を許可しない（個別のみ）」                                |

既定が `allow` の場合、`AppGrant` の行がなくても入場できます。既定値が空の場合は、ログインするユーザーに `allow` の `AppGrant` を付与します。`none` の行があるユーザーは入場できません。seed 管理者の共通ロールが `admin` であっても、`AppGrant` は自動では付与されません。`admin` や `user` という文字列は利用許可として扱われません。

アプリ未登録、戻り先 URL の不一致、実効許可が付与なしの場合、認証サーバーは 403「引き渡し先のアプリを利用できません」を返します。参加アプリの `/callback` には戻りません。

## 公開フロントと入場

未ログインの状態で `APP_ORIGIN/` を開きます。公開フロントを表示し、引き渡しは始めません。ヘッダはブランド色で、アプリ名と「ログイン」を出します。「ログイン」のリンク先は `/admin` です。

未ログインで `/admin` を開くと、`{AUTH_ORIGIN}/auth/handoff` へリダイレクトします。認証サーバーにセッションがあり、パスキーを登録済みで、実効許可が `allow` の場合は、`/callback` を経由して `/admin` に戻ります。戻り先は `/admin` です。

`/admin` には次の情報が表示されます。

- 見出し「ログイン中」
- メールアドレス、名前、共通ロール（`admin` は「管理者」、`manager` は「ユーザー管理者」、`user` は「一般ユーザー」）
- 利用許可「利用可」

管理画面のヘッダは黒です。左サイドバーに「管理」を表示し、本文は大きい画面でサイドバーの右に出します。セッションがある場合は「ログアウト」を表示します。利用許可がない画面でも同様です。「利用許可の例外」と「アプリ内ロール」も管理画面のヘッダに表示します。前者は共通ロールが管理者の場合だけ、後者は管理者またはユーザー管理者の場合に表示します。`/logged-out` のヘッダには「ログイン」を表示し、リンク先は `/` です。公開フロントを表示し、このページから引き渡しは始めません。

入場後、`APP_ORIGIN` の Cookie は `__Host-session` だけになります。`__Host-handoff` は引き渡しの往復中だけ存在し、`/callback` の応答で削除されます。

## ログアウト

参加アプリでログアウトすると、そのユーザーの全アプリ、全ブラウザ、全端末のセッションが Redis から削除されます。認証サーバーでログアウトした場合も、対象範囲は同じです。ログアウト操作はヘッダの「ログアウト」だけで、`POST /logout` を使います。参加アプリから認証サーバーへの HTTP リクエストは行いません。`/logged-out` には「ログアウトしました」と「ホームへ戻る」を表示し、ヘッダには「ログイン」を表示します。

`APP_ORIGIN` では `__Host-session` と `__Host-handoff` がその場で消えます。認証サーバーや他の参加アプリのホストに残る Cookie は、次にそのホストを開いたとき、Redis にキーが無いので削除され、未認証になります。

`/logged-out` からは引き渡しを開始しません。Cookie を確認する間は、この画面に留まります。「ホームへ戻る」とヘッダの「ログイン」は `/` で、公開フロントを表示します。引き渡しは始めません。フロントの「ログイン」から `/admin` を開くと引き渡しが始まります。認証サーバーのセッションも削除されているため、ログイン画面が表示されます。

## 権限

| 操作                                                                                     | 結果                                                                                                                           |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 未ログインで `/` を開く                                                                  | 公開フロント。引き渡しは始まらない                                                                                             |
| 既定を `allow` にし、行が無いユーザーで `/admin` を開く                                  | 「ログイン中」                                                                                                                 |
| 共通ロールが `admin` で `/grants` を開く                                                 | このアプリの例外一覧。列はメールアドレス、名前、利用許可                                                                       |
| 共通ロールを `manager` または `user` にして `/grants` を開く                             | 403「この画面を利用する権限がありません」。本文は `/` へのリンク。ヘッダはログアウト                                           |
| 共通ロールが `admin` または `manager` で `/roles` を開く                                 | 「割り当てられるアプリ内ロールはありません」                                                                                   |
| 共通ロールを `user` にして `/roles` を開く                                               | 403「この画面を利用する権限がありません」。本文は `/` へのリンク。ヘッダはログアウト                                           |
| 入場中に、そのユーザーへ `none` を付ける、または既定が空のまま行を外して `/admin` を開く | 「このアプリを利用する権限がありません」。操作はヘッダのログアウトだけ                                                         |
| 実効許可を `allow` に戻して `/admin` を開く                                              | 「ログイン中」に戻る                                                                                                           |
| 入場中に `disabledAt` を付けて `/admin` を開く                                           | このアプリの画面は出さず、引き渡しへ送る。そのユーザーの全セッションは消える。認証サーバーは無効ユーザーにセッションを出さない |
| 認証サーバーまたは参加アプリでログアウトしたあと `/` を開く                              | 公開フロント。引き渡しは始まらない                                                                                             |
| ログアウトしたあと `/admin` を開く                                                       | 自動では戻らず、認証サーバーのログイン画面に着く                                                                               |

## Cookie

開発者ツールの Application → Cookies で、ホストごとに見ます。`__Host-session` と `__Host-handoff` は `HttpOnly` なので、ページ上の JavaScript からは見えません。`Domain` は無く、参加アプリと認証サーバーは別の Cookie です。

| 時点                         | `APP_ORIGIN`          |
| ---------------------------- | --------------------- |
| `/admin` に入場したあと      | `__Host-session` だけ |
| `/logged-out` に留まったあと | どちらも無い          |
| `/` を開き直したあと         | どちらも無い          |
| `/admin` を開き直したあと    | `__Host-session` だけ |

`__Host-handoff` の寿命は 5 分です。ログイン後の画面に残っているときは、引き渡しが完了していません。
