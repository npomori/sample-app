# ロール対応の参加アプリ

この下書きは、リポジトリ `sample-app-roles` の仕様です。このリポジトリの参加アプリ（公開パス `/`、管理画面 `/admin`、アプリ内ロールなし）は変えません。確定した画面は [docs/access.md](../docs/access.md) です。

共通ロール、利用許可、アプリ内ロールの分け方は、認証サーバーの [auth-app-role-authorization-spec.md](https://github.com/npomori/auth-server/blob/main/planning/auth-app-role-authorization-spec.md) に従います。入場、Cookie、利用許可、`/grants` の手順は [app-permissions](app-permissions/README.md) に従います。更新の足し方は [docs/building.md](../docs/building.md) の「更新を足すとき」に従います。この下書きは、その具体化だけを書きます。

## 識別子

| 項目 | 値 |
| --- | --- |
| リポジトリ | `sample-app-roles` |
| `APP_ID` | `roles` |
| 表示名 | ロール見本 |
| 公開パス | `/` |

表示名は integration の `displayName` です。画面へ直書きしません。

## ロール

ロール名は固定です。運用中に名前を増やす画面は置きません。

| ロール | 見本の項目 |
| --- | --- |
| `editor` | 変更できる |
| `viewer` | 閲覧だけ |

利用者一人につき、今の割り当ては1件です。変更は置き換え、解除は行を消します。行が無い利用者の表示は「未割り当て」です。

## 認可

入場は実効許可が `allow` のときだけです。アプリ内ロールも共通ロールも、入場には使いません。判定は [grant.md](app-permissions/grant.md) です。

見本の項目を変更できるのは、次の場合だけです。

- 共通 `admin`。割り当てがなくても、`viewer` でも変更できる
- 共通 `user` または `manager` で、保存された割り当てが `editor`

共通 `manager` は、割り当て・変更・解除ができます。`manager` であることだけでは、見本の項目を変更できません。`editor` が保存されているときだけ変更できます。

共通 `user` は、`editor` のときだけ変更できます。`viewer` と未割り当ては閲覧だけです。

サーバーは、保存した割り当てを読みます。クライアントが送ったロール名では分けません。

## データ

スキーマは `roles` です。`public` には置きません。このスキーマだけを、このアプリがマイグレーションします。`AppGrant` には書きません。共有の Prisma Client へ、このアプリのモデルは足しません。

割り当ては1テーブルです。主キーは `User.id` です。列は、その識別子と、`editor` または `viewer` です。メールアドレスはコピーしません。画面のメールアドレスと名前は、共有の `User` を参照します。

見本の項目は、同じスキーマの1行です。本文の列を1つ持ちます。

## 画面

`/` は公開フロントです。見出しは「ホーム」です。ヘッダは `bg-brand` で、表示名と「ログイン」を出します。「ログイン」のリンク先は `/admin` です。セッションは読まないため、ログアウトは出しません。

`/admin` は管理画面です。骨格は、このリポジトリの [docs/access.md](../docs/access.md) の `/admin` と同じです。入場後に、メールアドレス、名前、共通ロール、利用許可「利用可」を出します。加えて、自分のアプリ内ロール（無ければ「未割り当て」）と、見本の項目を出します。変更できる利用者には、その項目の更新フォームを出します。閲覧だけの利用者にはフォームを出しません。

`/roles` は、共通 `admin` または `manager` が、メールアドレスで `User` を引き、割り当てを `editor`、`viewer`、または解除に更新する画面です。対象は、実効許可が `allow` の利用者だけです。入場できない利用者には割り当てません。共通 `user` は 403「この画面を利用する権限がありません」で、`/` へのリンクを出します。この拒否は入場を確認したあとに行うので、セッションの TTL は延ばします。

## 更新

見本の変更は `POST /admin/note` だけです。`src/fetch.ts` の `mutations` と `routes` に登録します。`POST /logout` はライブラリが登録します。アプリ側では繰り返しません。

`POST /admin/note` は、上の「変更できる」場合だけ本文を書きます。それ以外で入場済みの更新は 403「この操作を行う権限がありません」です。未認証の更新は 401「ログインが必要です」です。引き渡しは始めません。許可リストに無い更新は 404「見つかりません」です。

割り当て・変更・解除は `POST /roles` です。同じく `mutations` と `routes` に登録します。共通 `admin` または `manager` 以外は 403「この操作を行う権限がありません」です。

## ライブラリ

`participant-app-base` は `/roles` を注入し、本文を「割り当てられるアプリ内ロールはありません」に固定しています。このサンプルの `/roles` は、その注入をアプリの画面へ差し替える口ができたあとで実装します。差し替え口はこの下書きの範囲外です。
